## What the source research changed

The original web review used `c779472cced97006856cfc186c955f69ad7d15ab`. This audit fetched current web `main` and checked the relevant changes through **`0c5a63b6a959cb385f75452cd413ff2f50648444`**. The schema migrations, media contract and WAV validator did not change in that comparison. The web has newer Nirmaan branding, task selection and workspace improvements. A repository revision is not proof of the revision deployed at the production URL.

1. **Upload must precede voice confirmation.** `finalize_field_media` queues media processing while the report stays a draft; `submit_field_capture` rejects files that are not ready. Therefore, build roadmap **1.5 before 1.4**. Voice upload may resume automatically, but submission waits for the reporter to check the transcription. [Existing media contract and SQL](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/supabase/migrations/202609210011_field_media.sql).
2. **The transport approval needs a concrete extension.** Existing D5 approval covers step 1.1 reads only. Propose authenticated reads and the existing business RPCs for the remaining mobile flows, plus Storage uploads to reserved paths under existing RLS. The web API session helper uses browser cookies; a native access token cannot simply be supplied to those routes and assumed to work. [Web session helper](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/apps/web/src/lib/api.ts), [reserved upload policy](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/supabase/migrations/202609210011_field_media.sql).
3. **Confirmation must reflect available data.** The submit contract accepts wording, an optional work date and an optional selected activity. It does not expose a pre-submit AI match or a separate partial-work boolean. Propose authorized task selection, visible unfinished-work wording and explicit review of the final text; do not fabricate backend fields or suggestions. [Submit contract](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/packages/contracts/src/media.ts), [current web form](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/apps/web/src/components/report-form.tsx).
4. **Acceptance and independent verification are different operations.** Manager decisions need the real preview/acceptance contract and stale-version handling. Reporter clarification and independent supervisor responses must also have usable screens, or the mobile workflow stops at those states. The original feature description conflates these operations. [Existing follow-up migration](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/supabase/migrations/202609210005_clarification.sql).
5. **History was approved but omitted from the roadmap.** The shell contains a placeholder and the web already uses `execution_history`. Include it explicitly. [Web History screen](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/apps/web/src/app/planner/history/page.tsx).
6. **Exports have a transport decision, not just a missing button.** The current web creates a snapshot and serves a verified ZIP through its cookie-authenticated route. It does not establish the originally illustrated queued/generating state machine. Propose a browser handoff with web sign-in to preserve the existing backend. A fully native authenticated download would require a separate agreed solution and potentially one additional web PR. [Export implementation](https://github.com/ShivenduShivu/SIH122/blob/0c5a63b6a959cb385f75452cd413ff2f50648444/apps/web/src/lib/exchange-api.ts).

## Decisions included in the requested approval

Approval of this proposal would approve the following specific choices together, so they do not have to be asked again at each slice:

- **Order and cadence (D8):** execute the table sequentially, one bounded PR at a time; finish required checks, signed commits, push and observed CI before the next slice. Keep dependent PR bases explicit while owner reviews/merges are pending. Never merge PRs on the owner's behalf.
- **Transport (D5 extension):** existing authenticated Supabase reads/business RPCs and reserved-path Storage writes under existing production RLS for these flows. No schema changes, service-role access or replacement web APIs. Inspect the exact contract again at the start of each slice.
- **Offline voice (D7):** automatically resume draft upload when the foreground app reconnects with a valid session; require explicit confirmation before voice submission. Retry an already-confirmed, persisted payload without changing its ID/content. Do not promise uploads while the app is closed.
- **Status (D11):** foreground polling with backoff and resume/connectivity handling; stop when inactive/offline. Realtime is deferred until its production publication is verified.
- **Draft retention:** extend the already approved SQLite/app-private-file, same-account, retain-on-logout, explicit-discard behavior to text/photo drafts. Keep unsent evidence until a verified handoff or explicit discard.
- **Confirmation adaptation:** use the current source contract's optional authorized task selection and reviewed text for unfinished work; no invented pre-submit AI match or unsupported partial-work field.
- **Languages (D4):** English first for the early demo, English and Hindi by slice 14. Alerts/push and Tamil remain unapproved scope.
- **Exports:** browser handoff to the existing authenticated web export/download flow for the baseline. If a native download/share experience is required instead, revisit scope before slice 15; do not silently add a backend change.

The package ID, production target, local debug signing, current navigation and existing voice-draft retention are already approved and are not being requested again.

## External inputs and honest timing

The previous broad day-based estimate was not a measured execution forecast. It should not be treated as a deadline commitment. The completed cached Android build alone took 12 minutes 19 seconds; CI, native rebuilds, production worker responses and device checks have real elapsed costs that faster code generation does not remove. This sample does not establish the duration of every future PR.

The first meaningful deadline target is **five additional PRs to the Field demo**, rather than waiting for the complete fifteen. After the first new PR, record observed implementation/check/build time and update the remaining estimate from actual throughput. Track active implementation time separately from waiting for owner input, CI, hardware or backend access.

Work on local capture and contract-tested services can proceed after plan approval. Live integration evidence additionally requires:

- The publishable/anon key supplied locally in the ignored `.env.local` using the already specified variable name. It is currently blank; no password, service-role key or signing secret belongs in the project configuration.
- Owner-designated test project and appropriately scoped reporter/planner/supervisor sessions within the selected production project. Test records must not change an unrelated live construction plan.
- A working deployed media worker/transcription configuration and the reviewed migrations/policies. Source inspection has not verified these deployments. If missing, identify the concrete blocker; do not change production schema or worker infrastructure without a separate decision.
- An available physical Android phone for the checks that an emulator cannot establish. Record unperformed checks as pending, never as passed.

Review comments and unforeseen integration failures may add work. Fixes normally stay in their owning PR; a newly required architecture/backend change may add another PR. This proposal does not reserve or guarantee GitHub PR numbers.

## Implementation research references

- [Expo ImagePicker](https://docs.expo.dev/versions/latest/sdk/imagepicker/): camera/library permissions and Android interrupted-result recovery. Review its native permission configuration alongside the existing recorder.
- [Expo ImageManipulator](https://docs.expo.dev/versions/latest/sdk/imagemanipulator/): resize/re-encode actual image data to accepted formats before declaring MIME/size and persisting it. The existing backend accepts at most three JPEG/PNG/WebP photos and one WAV, with a 5 MiB per-file limit; a changed filename is not conversion.
- [Supabase upload reference](https://supabase.com/docs/reference/javascript/file-buckets-upload) and [Storage access control](https://supabase.com/docs/guides/storage/security/access-control): implement binary upload with explicit content type and no overwrite, constrained by the existing reserved-path policy.
- [TanStack Query on React Native](https://tanstack.com/query/latest/docs/framework/react/react-native): native focus/connectivity need explicit integration for reconnect/status refresh; server state remains in React Query.
- [Expo APK guide](https://docs.expo.dev/build-reference/apk/): an installable preview must be an APK; record the actual build mode/device compatibility and test installation. The currently built emulator debug app does not satisfy the independent phone-preview milestone.

Documentation proposal validation: formatting and internal-link/path checks. No application behavior is changed by this document, and no new feature is claimed complete.
