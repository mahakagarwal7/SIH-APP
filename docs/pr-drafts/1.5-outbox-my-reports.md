## Behavior and scope

Roadmap 1.5 turns complete local voice/text/photo drafts into a restart-safe outbox. It freezes stable capture/media IDs and SHA-256 manifests, rechecks current membership, reserves through the existing RPC, uploads only to reserved production Storage paths without overwrite, finalizes media work and polls in the foreground until evidence needs confirmation. Interrupted reserve/upload/finalize calls retry the same identity and completed file list.

My reports replaces its placeholder with account-scoped device/server records and honest Saved on device, syncing, processing, Needs confirmation, Awaiting review, Accepted, Partly accepted and follow-up states. A last verified project context permits new offline capture but is never used as server authorization. Expired auth or revoked membership pauses delivery without deleting evidence.

This PR is stacked on **PR #6, `feature/1.3-text-photo-capture`**. It does not call `submit_field_capture`; confirmation/submission remains roadmap 1.4. It changes no production schema, web API, RLS policy or worker.

## Contract and assumptions

- Existing authenticated Supabase reads/business RPCs and reserved-path Storage writes are used under production RLS.
- `captureId` is the durable local draft ID. Text/photo attachment IDs remain stable; voice gets one persisted media UUID before reservation.
- Actual private bytes are re-read and checked against byte count and SHA-256 before each first upload.
- Duplicate Storage insert responses are recoverable lost-success retries. `upsert` stays false; the worker remains the final byte/hash validator.
- Local evidence is retained after entering the outbox and through Needs confirmation.
- Foreground reconnect/polling uses bounded backoff. No background-while-closed claim is made.

See [the outbox contract](../OUTBOX_SYNC.md) and the [approved delivery sequence](../DELIVERY_PLAN.md).

3. Reconnect in the foreground. Confirm each capture reserves once, uploads only its frozen files and survives a killed/restarted app during every phase.
4. Retry after an intentionally lost upload response. Confirm one server report/capture exists and no file is overwritten.
5. Wait for the real worker. Confirm successful voice/photo media reaches Needs confirmation and nothing appears in the planner review queue yet.
6. Expire the session and revoke membership separately. Confirm Sync paused, no repeated mutation and no local evidence loss. Restore access and use Sync now.
