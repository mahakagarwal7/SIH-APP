## TL;DR

Durable device drafts now resume through an account-bound outbox into **Needs confirmation**, and My reports keeps delivery and review outcomes separate. The review fixes address all 12 reported findings and integrate the completed PRs 1–6 from main `b0d600d` without discarding their regression coverage. This PR targets **main**. It does not submit reports for review.

## Behavior and scope

Roadmap 1.5 turns complete local voice/text/photo drafts into a restart-safe outbox. It freezes stable capture/media IDs and SHA-256 manifests, rechecks current membership, reserves through the existing RPC, uploads only to reserved production Storage paths without overwrite, finalizes media work and polls in the foreground until evidence needs confirmation. Interrupted reserve/upload/finalize calls retry the same identity and completed file list.

My reports replaces its placeholder with account-scoped device/server records and honest Saved on device, syncing, processing, Needs confirmation, Awaiting review, Accepted, Partly accepted and follow-up states. A last verified project context permits new offline capture but is never used as server authorization. Expired auth or revoked membership pauses delivery without deleting evidence.

It does not call `submit_field_capture`; confirmation/submission remains roadmap 1.4. It changes no production schema, web API, RLS policy or worker.

## Review fixes

- Bind each transport to the saved account, preventing a switch after membership/reservation from sending the previous account's evidence with the new account's token.
- Wake foreground sync after durable saves/enqueues and manual sync; preserve an explicit retry requested during an automatic pass.
- Coordinate save, outbox preparation and discard with one capture lock, checking outbox ownership inside the native deletion guard.
- Persist retryability: transient errors retry with bounded backoff, terminal worker errors stay stopped, and explicit retries still recover paused access or restored local files.
- Read every claim page for the latest 100 reports; incomplete/inconsistent results fail visibly. Preserve `observed` and prioritize unresolved follow-up over partial acceptance.
- Surface online project errors despite cached data, restore the Sync button after navigating away during a pass, and label unknown remote attachment counts honestly.
- Raise empty-state text contrast to approximately 4.96:1 against its page background.

The merge retains earlier authentication, navigation, voice, text/photo, dependency and request-handling fixes. Regression tests cover account switches between real Supabase request-builder phases, both deletion/preparation orderings, coordinator wakeups/retries, SQLite migration, paginated mixed statuses, cached access errors and tab navigation during sync.

## Contract and assumptions

- Existing authenticated Supabase reads/business RPCs and reserved-path Storage writes are used under production RLS.
- `captureId` is the durable local draft ID. Text/photo attachment IDs remain stable; voice gets one persisted media UUID before reservation.
- Actual private bytes are re-read and checked against byte count and SHA-256 before each first upload.
- Duplicate Storage insert responses are recoverable lost-success retries. `upsert` stays false; the worker remains the final byte/hash validator.
- Local evidence is retained after entering the outbox and through Needs confirmation.
- Foreground reconnect/polling uses bounded backoff. No background-while-closed claim is made.
- Server history currently covers the latest 100 reports. Claim summaries page through readable claims for those reports, failing visibly above 10,000 claims or when pagination is inconsistent.
