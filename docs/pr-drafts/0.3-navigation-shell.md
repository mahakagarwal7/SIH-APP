## Contract and decisions

- One auth provider owns the session controller and lifecycle subscriptions across screens. Resume checks preserve entered credentials while signed out and keep a valid signed-in session visible without navigation resets. Expiry, failed restore and sign-out close protected routes; stale restore results cannot overwrite a newer sign-in.
- Expo Router's protected stack blocks direct links while signed out/loading/unconfigured/in error and removes protected history after session loss. This is a client UI boundary, not a substitute for backend authorization.
- Workspace selection only changes presentation. It does not assign membership or permissions; no project queries, business API requests, schema/RLS changes or feature mutations are added.
- Production configuration keeps the exact public names and remains local. There is no demo-login bypass. Browser interaction checks use intercepted auth responses with synthetic credentials.
- `@expo/vector-icons` and `expo-font` provide the design's restrained outline tab icons. Expo font support is configured in the app plugins; no UI framework is added.
- Real membership/project selection, language support, v1 Alerts/push, business transport, capture, review operations and exports remain future work. Stop after 0.3.

## Manual device checks

1. Fill the local public key and restart Expo with `npx expo start --clear`. Sign in with an existing approved account. Verify that the workspace chooser opens; neither entry implies project access.
2. Enter Field and visit all four tabs. Open Change project, confirm the explicit unavailable message, then Back; expect the same tab. Open Account and Back with the same result.
3. Use Account > Switch workspace, enter Manager and visit its four tabs. Check hardware Back and repeated switches without duplicate screens or stale tab content.
4. While signed out, enter credentials, switch to another app and return; both inputs must remain. Background/resume with an unexpired session on a non-home tab; expect that tab to stay selected. Let the session expire, revoke refresh access in an approved test environment, or sign out; protected pages must close. Attempt a direct link and Back while signed out; expect the auth screen.
5. In airplane mode, keep a valid session and navigate the shell; expect the offline banner and no invented sync status. Check online/offline sign-out and unavailable secure storage using the auth slice's manual checks.
6. On a physical phone, check large text, portrait/landscape, safe areas, tab labels/icons, screen-reader selected states, and reachable account/project controls. Verify native session persistence after a restart.
7. In web preview, reload a protected URL; expect sign-in because browser sessions are memory-only. For static exports, the preview host must fall back to `index.html` for client routes; Expo's development server already handles routing.
