# PR: Fix production data sync and mutating-action feedback

## Behavior and scope

Phase 9 fixes the mobile causes behind misleading zero/empty states and blocked
actions across Field Home, My Work, My Reports, Manager Progress Overview and
claim decisions. It also completes the voice-review work-date path, guards
queued evidence from destructive discard, exposes workspace switching in the
persistent header and adds one app-wide auto-dismissing toast provider.

This is the owner-approved single PR for `DATA_SYNC_AND_UI_FIXES.md` sections
9.0 through 9.2 and 9.4 through 9.8. The owner explicitly deferred section 9.3
on 25 September 2026. The commits remain logically separated inside the PR.

## 9.0 investigation and actual causes

- Local configuration uses the approved `NEXT_PUBLIC_SUPABASE_URL` and
  `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` names. `app.config.ts` deliberately
  maps them into Expo runtime config. The configured URL is exactly
  `https://dgxflhdcthyborxjyfvv.supabase.co`, the production project supplied
  for the web app. The public key is present locally and is not committed.
- A read-only anonymous production check returned no visible `projects`,
  `project_members` or `reports` rows and no PostgREST error, which is
  consistent with RLS hiding account data without a session. No designated
  production user session or SQL-editor access exists in this workspace, so
  same-user RLS parity for `Urban Garbage Treatment Plant · Town XYZ` remains a
  manual owner check rather than claimed evidence.
- The deployed web URL returned HTTP 200 during the audit. Authentication was
  unavailable, so no side-by-side user/project comparison was claimed.
- This was not one backend-project mismatch. The mobile causes were distinct:
  1. Field Home aggregated every activity in the project snapshot instead of
     only the signed-in reporter's latest assignments.
  2. My Work required both the latest assignment row and a denormalized
     snapshot reporter field to agree. A lagging snapshot field could silently
     exclude otherwise valid current assignments.
  3. My Reports merged `remote.data ?? []` and rendered the genuine-empty copy
     even when the server query had failed. It also did not directly react to
     every local outbox change.
  4. Manager Overview calculated total and discipline bars only from accepted
     finishes, ignoring backend-provided partial `acceptedPercent` values.
  5. Accept appeared disabled until a separate preview tap. The primary action
     now enables after valid inputs, displays the before/after preview on its
     first tap, and requires a separate confirmation before the durable write.
  6. Queued-draft protection surfaced as a tappable action followed by an
     error. The state is now explained and disabled before the destructive
     action.
- React Query now logs the original failed query/mutation and cache key through
  a development-only warning. Screens touched here preserve separate loading,
  empty, error and retry states instead of turning failures into empty data.

## Contract and decisions

- Field reads continue through authenticated, RLS-protected
  `project_members`, `assignment_versions`, `schedule_snapshot(p_project)`,
  `reports`, `claims` and `jobs`. No service-role credential, private key,
  policy bypass, schema change or new web API was added.
- Latest `assignment_versions` rows are the personal-work authority. Snapshot
  activities provide the activity and accepted-actual fields. Home averages
  accepted percentages only across those assigned activities; an accepted
  finish contributes 100. Quantity is never converted into a percentage.
- Manager total and discipline bars average the backend-provided accepted
  activity percentages. Finished/planned counts stay visible as separate
  context. Empty schedules keep a dash rather than a fabricated 0%.
- Accept still uses the existing `preview_claim` and `decide_claim` RPC
  contracts with exact versions and preview hash. The manager sees the proposed
  change before confirming it. Reject remains independent
  of preview and activity selection, but still requires a written reason. This
  follows `docs/MANAGER_DECISIONS.md` and the production command schema, which
  explicitly require a non-empty reason; the phase note suggesting reasonless
  rejection conflicts with that reviewed contract.
- Voice review now renders the shared native work-date picker before Submit.
  An early Send request stores the selected date in SQLite and applies it when
  the verified transcript later becomes ready. Reopening a queued report shows
  that saved date.
- A purely local draft can still be discarded. A queued/uploading copy is
  retained because the outbox needs its bytes; its Discard button is disabled
  with an explanation. Discard also stays disabled until the outbox check has
  succeeded. A submitted copy becomes discardable only after durable receipt
  fields exist.
- `ToastProvider` is mounted once at the app root. Report send/save/discard,
  claim accept/reject and explicit sync outcomes use this shared non-blocking
  feedback path.
- The persistent header now exposes both Switch workspace and Change project.

Garbage Treatment Plant · Town XYZ`, and compare Home and My Work activity

2. Submit a text/photo report. Confirm each exact capture appears in My Reports
   without an app restart and status changes after manager acceptance.
3. On voice review, tap Submit without a date, confirm the date validation is
   actionable, choose today or an earlier date, and confirm Submit queues the
   report with that date. Reopen the queued report and confirm the date remains
   visible.
4. Compare Manager Overview total and all nine discipline percentages with the
   web app's accepted activity actuals for the same revision.
5. Type an acceptance reason, choose a valid candidate, tap Review before
   acceptance, inspect every before/after field, then tap Confirm acceptance.
   Verify the claim leaves Review. Repeat Reject with the production-required
   reason and verify its durable decision.
6. Discard a purely local draft. Then inspect a queued/uploading draft and
   verify Discard is disabled with the device-copy explanation and no error.
   Repeat while the outbox check is loading or failed; Discard must remain
   disabled and the failed check must be retryable.
7. From Field and Manager nested screens, use Switch workspace and Change
   project; verify both remain available and preserve their existing behavior.
8. Trigger send, discard, accept, reject and explicit sync success/failure;
   verify each toast auto-dismisses without blocking the underlying screen.
   A failed or paused outbox item must not show a success toast, and a queued
   cancellation must not claim that the report was already discarded.
