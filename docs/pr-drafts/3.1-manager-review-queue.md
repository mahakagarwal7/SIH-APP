## Behavior and scope

The Manager Review tab was a placeholder. Roadmap 3.1 replaces it with a production-RLS-backed, read-only queue for unresolved claims. Managers can inspect the original field report, extracted claim context, validation flags and ranked activity candidates with match reasons across exact-count server pages.

## Contract and decisions

- Reads existing `claims`, `reports`, version 1 of `report_versions`, `candidate_matches`, received `attachments`, `project_members` and `schedule_snapshot(p_project)` through the authenticated Supabase client.
- Includes the web review filter's unresolved states: pending, clarification, verification and disputed. Decision writes remain roadmap 3.2.
- Accepts only active planner/manager project contexts, rechecks membership and role after the page read, and rejects incomplete or cross-project results.
- Treats report version 1 as the verbatim original report. The extracted claim evidence remains visible for later follow-up versions.
- Shows original audio transcript and photo/capture metadata from the report snapshot, with RLS-authorized attachment links signed for one minute on tap. Correction claims are explicitly marked with the accepted event they replace.
- Preserves production-valid empty nullable text and the observation-v2 contract; expanded cards show structured progress basis, coverage dates, daily quantity, percentage basis and explicit item IDs.
- Resolves candidate labels from the active schedule when possible and identifies candidates from older schedule revisions without inventing replacement activities.
- Keeps stale cached pages visible after transient refresh failures with a warning, hides them after confirmed access denial and recovers when queue changes invalidate the selected page. Clears review-query caches during project switches; review data is not written to local storage.
- Adds no dependency, schema, policy, service key or web API change. See `docs/REVIEW_QUEUE.md` for the detailed read contract and consistency boundary.

## Manual device checks

1. Configure the public production URL/key locally and sign in as a planner or manager with unresolved claims in two projects.
2. Open Manager → Review. Confirm the selected project's count and first page match the web review queue for pending, clarification, verification and disputed states.
3. Expand a voice, text and follow-up claim. Compare the original report text, audio transcript/photo metadata, evidence quote, validation flag, reporter, dates and candidate ranking with the web review panel; open a received media file and confirm its short-lived link works.
4. Change project. Confirm the old project's claim cards disappear before the new page loads, then switch back and verify pagination.
5. Open a candidate tied to an older schedule revision. Confirm the recorded candidate remains identifiable and the app does not substitute a current activity.
6. Revoke or downgrade the test membership, then refresh. Confirm the queue disappears and manager access is denied.
7. Load a page, enable airplane mode and reopen Review. Confirm cached content is marked stale, refresh is disabled and an uncached page is not fabricated.

## Remaining limitations

- Live production-RLS and physical-device evidence remain pending local public configuration and designated accounts.
- This slice is read-only. Activity selection, preview, accept/reject reasons, clarification and independent verification are roadmap 3.2.
- Separate Supabase reads cannot guarantee an atomic queue snapshot; detected incomplete or mixed-project results are rejected and claim changes require refresh.
- Terminal accepted/rejected records belong in the later History slice.
