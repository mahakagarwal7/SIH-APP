# feat(ui): establish the Nirmaan mobile foundation

## Behavior and scope

Roadmap 0.1 adds an Expo SDK 57 / React Native 0.86 foundation with a single Nirmaan launch route. The app can open without backend configuration. The launch design uses the navy serif masthead, white surface and thin rules from design-book page 8, adapted to this slice's minimal welcome screen.

Strict TypeScript, ESLint/import ordering, Prettier, Jest, a lockfile, a pinned Node runtime and read-only GitHub Actions checks provide the starting point for later slices. No feature screens are represented as complete.

## Contract and decisions

- Owner confirmed Nirmaan as the mobile name and production as the backend.
- No tables, RPCs or network requests are used by the foundation.
- Keep the exact public environment names `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Runtime wiring belongs to 0.2.
- App slug and URL scheme are local development identifiers; no Android application ID, EAS project or signing identity is created.
- Android uses its platform serif; iOS uses Georgia and the web uses Georgia/serif. Custom font selection remains open.
- New root configuration files are required by Expo, TypeScript, ESLint, Jest, Prettier and reproducible Node/Git setup.
- Runtime dependencies provide Expo, React Native, routing, safe areas, linking, status-bar control and browser previews. Reanimated/worklets are pinned to the SDK versions required by the router dependency tree. Development dependencies provide TypeScript, ESLint, formatting and the Expo/React Native test renderer; `test-renderer` is pinned to 1.2.0 to match React 19.2.

## Validation

- Observed the launch test fail for the missing accessible welcome heading before implementing the screen.
- `npm run typecheck`, `npm run lint`, `npm run format:check` and `npm test -- --runInBand`: passed locally; one launch test, no snapshots.
- `npx expo install --check`: dependencies match SDK 57.
- `npm run bundle:check`: exported Android and iOS Hermes bundles plus the static web preview.
- Chromium preview at 390 x 844 and 320 x 568: welcome heading visible, no horizontal overflow or clipped text. Appearance compared with design-book page 8. No backend requests were observed. The temporary static server returned a harmless 404 for the browser's default favicon request.
- CI repeats the checks with a fresh `npm ci` on pull requests; see the PR checks for remote results. Bundle success is not physical-device or APK evidence.
- Commits use the owner's GPG key `831C481EF8506935` and are verified locally before push. GitHub's signature status is checked separately after push.

## Manual device checks

1. Use Node 22.19.0, run `npm ci`, then `npm start`.
2. Open the app in a compatible Expo Go client or Android emulator. Confirm Nirmaan, the welcome heading and Mobile preview appear without credentials.
3. Increase the system font size and check portrait and landscape. Text should wrap and the screen should scroll; content must clear status and navigation bars.
4. Enable TalkBack and confirm the welcome is announced as a heading.
5. Disable network access after loading the development bundle. The static launch screen should remain usable; this is not an offline-reporting test.

## Remaining limitations

The publishable key is still absent from local web configuration. Auth, backend access, navigation decisions, feature data, recorder, outbox and APK delivery are outside 0.1. No physical device, Android emulator or live backend was tested.

`npm audit` reports 13 moderate findings through Expo's `xcode`/`uuid` tooling and the router's `query-string`/`decode-uri-component` dependencies; no high or critical findings were reported. The suggested automatic fixes downgrade Expo/router across incompatible major versions and were not applied. Reassess upstream fixes before adding authenticated navigation or distributing an APK.
