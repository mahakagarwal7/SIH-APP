## Behavior and scope

Managers could inspect unresolved claims but could not act on them from mobile. Roadmap 3.2 adds a dedicated decision screen with verbatim evidence, deliberate activity selection, an exact before/after acceptance preview, preview-hash confirmation, reasoned rejection, reporter clarification and independent supervisor verification.

## Contract and decisions

- Calls existing `preview_claim`, `decide_claim`, `request_clarification` and `request_verification` functions through the authenticated Supabase client under production RLS.
- Uses direct business RPCs because the existing Next.js routes require browser cookie authentication and same-origin requests. This is the transport already approved in `docs/DELIVERY_PLAN.md` D5; no mobile bearer-token assumption or replacement API was added.
- Re-reads claim, report, candidates, active schedule/actuals, active verification and planner/manager membership before enabling actions.
- Requires explicit candidate selection. Acceptance is unavailable for mismatched candidates, unresolved flags, stale revisions or an invalid/missing required work date.
- Reuses one command ID for an unchanged retry. Acceptance must send the hash from the exact preview; changed input clears that preview.
- Removes accepted/rejected claims and updates totals across same-project queue caches immediately, then invalidates server state. Other projects are untouched.
- Keeps clarification and supervisor verification separate from acceptance. Reporter/supervisor response screens remain the next approved slice.
- Adds no dependency, schema, policy, service-role secret or web-backend change. See `docs/MANAGER_DECISIONS.md` for the detailed contract.

## Manual device checks

Use only owner-designated production test claims; accept/reject are durable records.

1. Sign in as a planner or manager, open Manager → Review, open a pending claim and confirm no candidate is preselected.
2. Select a clean candidate and enter a reason. Preview, then compare every before/after field with the web review panel before accepting.
3. Accept the designated test claim. Confirm it leaves the unresolved queue immediately, the queue total changes once, and the web shows the same accepted event and decision reason.
4. Reject a separate designated claim with a reason. Confirm no activity actual changes and the web shows the rejected state.
5. Request a location/date/scope clarification. Confirm the reporter receives one open question and no work is accepted.
6. Request supervisor verification for an eligible assignment exception. Confirm the assigned verifier sees the exact claim/activity and the manager cannot accept before confirmation.
7. Open the same claim on web and mobile, preview on mobile, then change/accept it on web. Confirm mobile rejects the stale preview and reloads current versions.
8. Interrupt connectivity after pressing each action, reconnect and retry without changing inputs. Confirm the command is recorded once.
9. Switch projects or revoke/downgrade membership before submitting. Confirm the old claim cannot be decided and no other project's cached queue changes.

## Remaining limitations

- Live production-RLS, cross-client and physical-device evidence remain pending designated test accounts and claims.
- This slice requests clarification and verification; reporter answers and supervisor attestations are the next planned PR.
- Unplanned/observation and rematch controls supported by broader web contracts are outside the roadmap 3.2 accept/reject scope.
- Separate client reads are not transactionally atomic; every mutation relies on existing database version checks.
