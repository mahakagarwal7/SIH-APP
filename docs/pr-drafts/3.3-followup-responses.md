## Behavior and scope

Requested clarification and independent verification previously stopped at an honest pending state on mobile. Roadmap 3.3 lets the report author answer the current structured question from My Reports and lets the routed independent verifier record assignment and work checks from My Work.

## Contract and decisions

- Calls existing `respond_clarification` and `decide_verification` functions through the authenticated Supabase client under production RLS.
- Uses direct business RPCs because the current Next.js routes require browser-cookie, same-origin sessions. This remains within approved delivery-plan decision D5 and adds no replacement API.
- Re-reads report/question/claim or verification/revision/membership context before enabling a response.
- Preserves backend question types, permitted location choices, real calendar dates, explicit uncertainty and separate assignment/work attestations.
- Reuses a command ID only while the complete payload is unchanged, so unknown-result retries remain idempotent.
- Refreshes the changed follow-up and related report/review caches. Stale writes retain entered text while current server state reloads.
- States throughout the UI that replies and supervisor checks do not accept progress; the planner decision remains separate.
- Adds no dependency, schema, policy, service-role secret, Alerts flow or web-backend change. See `docs/FOLLOWUP_RESPONSES.md` for the detailed contract.

## Manual device checks

Use only owner-designated production records; replies and attestations are durable audit events and a concrete clarification can queue new processing.

1. As a reporter, open Field → My reports and a submitted report with an open clarification. Confirm the original wording, claim state, validation flags and exact current question match the web report detail.
2. Answer each supported question type on designated records: permitted location, typed location, date, scope, assignment and detail. Confirm a response never appears as accepted progress.
3. Choose **Not sure** on a separate question. Confirm the planner sees the uncertain response and any new question/manual-review state.
4. Open the same question on web and mobile, answer it on web, then submit the preserved mobile draft. Confirm mobile reports a stale question, retains the draft and reloads current history.
5. As the routed supervisor, open Field → My work → Supervisor checks. Confirm another supervisor and the original reporter cannot see or decide that request.
6. Record assignment and work as confirmed with a reason. Confirm the manager queue returns the claim to pending review and the schedule remains unchanged.
7. On separate checks, record **Cannot confirm** and **Need details**. Confirm disputed/verification states and earlier reasons match the web follow-up panel.
8. Change the active revision, policy, assignment or verifier before submitting a prepared check. Confirm mobile rejects the stale response and preserves entered details.
9. Switch project, revoke membership and test offline. Confirm old checks disappear, writes remain disabled and no other project's cache is changed.
10. Interrupt connectivity immediately after either write, reconnect and retry without changing fields. Confirm exactly one response or decision exists.

## Remaining limitations

- Live production-RLS, cross-client and physical-device evidence remains pending designated test accounts and records.
- There is no push/Alerts dependency; users open questions from My Reports and assigned checks from My Work.
- Report correction/withdrawal controls remain outside this approved response slice.
