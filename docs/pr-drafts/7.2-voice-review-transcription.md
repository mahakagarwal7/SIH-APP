# PR: Add immediate voice review and automatic transcription flow

## What this changes

Stopping a valid voice recording now completes the device write and opens a
review panel immediately. The panel provides raw-audio playback, a
“Transcribing…” state, and Cancel / Send actions without waiting for any network
request. The existing outbox coordinator starts reservation, upload,
finalization and worker polling as soon as the local save announces work.

Send can be tapped before the transcript exists. The app durably records that
intent in SQLite, continues the production media chain, and submits
automatically after the worker returns a verified non-empty transcript. If the
transcript arrives before Send, it appears on the same screen and remains
editable; the edited wording becomes the locked submission payload.

Cancel also persists its intent. For an unreserved capture it removes local
evidence without making a remote call. For a reserved capture it calls the
existing `discard_field_capture` RPC, then removes the app-private audio and any
companion evidence. Network interruption retains the cancellation tombstone
and private local evidence so foreground sync can retry without resuming upload
or submission.

## Production-contract constraint

The supplied fix note says an audio report can submit before transcription and
receive a transcript later. The reviewed production migration does not permit
that: `submit_field_capture` rejects any attachment that is not `received`, and
audio cannot become `received` until `complete_field_media` stores a non-empty
verified transcript. This implementation preserves the requested immediate
Send interaction as a durable local intent while respecting the deployed RPC
and worker contract. It changes no Supabase schema, RLS policy, RPC, worker or
web API.

## Tests

- Review actions render while outbox preparation is deliberately unresolved.
- Send before transcription is persisted and automatically reaches
  `submit_field_capture` after verified media becomes ready.
- A returned transcript appears in place and edited wording is passed to Send.
- Cancellation removes an unreserved local capture and its private bytes.
- Reserved cancellation survives a simulated network failure, retries
  `discard_field_capture`, and only then removes local evidence.
- SQLite migration/persistence covers Send and Cancel intent across restarts.
- Run `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test` and
  `npm run bundle:check`.

## Manual test

1. Sign in as a field user and record a one-second voice update.
2. Tap Stop. Verify the review panel, playback, “Transcribing…”, Cancel and Send
   appear without waiting for the network.
3. Throttle the network and tap Send immediately. Verify “Send queued” appears,
   then the transcript and final “Sent for review” state arrive after recovery.
4. Record again and wait without sending. When the transcript appears, edit a
   word and tap Send; verify My Reports contains the edited wording.
5. Record again and tap Cancel before reservation completes. Verify the review
   closes and the local draft disappears.
6. Start another upload, disconnect the network, and tap Cancel. Verify My
   Reports shows cancellation pending; reconnect and confirm the remote draft
   is withdrawn before the local evidence disappears.
7. Background and reopen the app after tapping early Send and early Cancel;
   verify each intent resumes in the correct direction.
