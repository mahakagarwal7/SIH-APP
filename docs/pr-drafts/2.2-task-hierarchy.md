## Behavior and scope

Roadmap 2.2 adds a read-only task hierarchy opened from Field **My work** or
Manager **Schedule**. Users can follow the selected activity's exact source
path, inspect direct visible child branches, and see assignment plus accepted
activity facts. Missing parents, leaf branches, limited field visibility,
loading, offline, no-access and changed/missing snapshot states are explicit.

This PR is stacked on draft PR #16 (`feature/4.1-read-only-schedule`) because it
reuses that slice's strict snapshot contract and adds the Manager Schedule entry
point. Review and merge its base first.

## Contract and decisions

- Calls the existing authenticated `schedule_snapshot(p_project)` RPC and then
  rechecks the same active `project_members` row, role and version.
- Uses production `schedule_nodes.parentId` relationships for planner/manager
  traversal. When RLS omits nodes for a field role, uses only the authorized
  activity's stored `hierarchyPath` and labels the view as limited.
- Rejects malformed snapshots, duplicate node identifiers, cycles,
  cross-project data, hidden activities and revoked/version-changed membership.
- Shows source level/WBS/kind and exact dates without inventing fixed L-levels.
  Accepted activity facts are not aggregated onto parent nodes.
- Resets branch focus when project, revision, schedule version or requested
  activity changes. Project switches clear the hierarchy query cache.
- Adds no dependency, schema, policy, RPC, secret, write path or backend change.
  See `docs/TASK_HIERARCHY.md` for the complete consistency boundary.

## Manual device checks

Use owner-designated reporter, supervisor, planner and manager accounts in one
project with a real imported hierarchy.

1. Open an activity from Field → My work. Confirm only its authorized stored
   path appears, the limited-visibility notice is present, and no sibling data
   leaks.
2. Open the same activity from Manager → Schedule. Compare every path node,
   parent, source level/WBS, planned date and direct child with the web schedule.
3. Select ancestors and child branches. Confirm the path updates and a leaf
   says that no child branches exist.
4. Compare the selected activity's assignment, accepted quantity, actual
   dates, percentage/basis and progress date with the web app. Confirm parents
   show no calculated progress.
5. Test a source snapshot with a missing visible parent. Confirm the gap is
   labeled and no replacement node is created.
6. Load a hierarchy, disable connectivity and reopen it. Confirm cached data is
   labeled stale and refresh is disabled; repeat before any cache exists.
7. Activate a designated replacement revision on web and refresh. Confirm the
   revision/version changes and branch focus resets to the requested activity.
8. Switch projects, revoke membership, and change a role/version. Confirm old
   hierarchy records disappear and unauthorized activity IDs reveal no data.

## Remaining limitations

- Live production-RLS, web/mobile parity, emulator and physical-device evidence
  remain pending designated accounts/projects.
- Field users cannot browse branches omitted by production RLS; the mobile app
  deliberately does not reconstruct or fetch them through another path.
- The slice is read-only. Editing hierarchy, assignments, schedules and
  accepted progress remains outside this screen.
