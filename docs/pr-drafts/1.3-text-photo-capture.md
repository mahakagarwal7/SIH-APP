## Behavior and scope

Roadmap 1.3 adds native typed reports and up to three captioned photos, saved to
account-scoped SQLite and app-private files before displaying **Saved on device**.
Failed saves retain the same draft ID, text and bytes for retry. Drafts survive
logout, remain visible only to their owner and require explicit discard.

The review fixes prevent a successful retry from racing with deletion, keep failed
discards visible and block saving until pending-photo recovery finishes. They also
fix the method selector's runtime exception, keep Voice / Type / Photo inside the
single Report tab, expose those methods on the non-Android voice screen, and restore
secondary-text contrast. Both Type and Photo forms accept wording with photos.

PRs 1–5 are now owner-merged. This branch integrates main `dae6f4b` and resolves all
27 conflicted paths while preserving the earlier auth, navigation, My work,
request/dependency and voice fixes. A duplicate legacy Report route introduced by
the merge was removed. Main and completed PR #5 had identical trees; the initial
resolution was checked against the clean merge with that completed PR #5 tree.
The PR targets **main**. No PR merge, upload, transcription, confirmation,
submission or backend mutation is part of this slice.

## Contract and decisions

- Existing media boundaries: at most three photos, JPEG/PNG/WebP, at most 5 MiB
  each and at most 20 million decoded pixels. Mobile normalizes picker inputs to
  JPEG and checks the resulting dimensions and byte length.
- Text is at most 10,000 characters; photo captions are at most 500 characters.
- `expo-image-picker` owns native camera/library interaction;
  `expo-image-manipulator` resizes and re-encodes photos. Output limits are checked
  after native decoding; this is not a bounded-memory decoder guarantee.
- The owner's SQLite/app-private, retain-on-logout, same-account and explicit
  discard decisions remain unchanged. Storage rejects overlapping mutations for
  the same account/draft; different drafts can progress independently.
- The approved sequence puts outbox 1.5 before confirmation 1.4 because voice
  transcription requires upload and media processing.

## Manual device checks

1. Install the native build and sign in as an authorized field account. Confirm
   exactly four Field tabs. Open Report and switch between Voice, Type and Photo
   without an error overlay or extra bottom tabs. On iOS, the voice-unavailable
   screen must still offer Type and Photo.
2. Enter work completed and remaining, add a captioned photo, save and restart.
   The same account must retain **Saved on device · Not sent for review**.
3. Deny camera/library permission, then grant it and capture/select a photo.
   Include a non-JPEG input where available; check up to three photos, removal,
   caption association and save. No unavailable capability should claim success.
4. Enable Android “Don't keep activities,” choose/take a photo and return.
   During **Restoring photo**, Save and picker actions must be disabled. Once
   recovered, save and restart to verify the image was included.
5. Exercise failed or interrupted persistence. Retry must retain the same draft
   identity and content. During **Discard incomplete save**, Retry and both
   discard actions must remain disabled until deletion finishes.
6. Exercise failed deletion. The draft and its retry action must remain visible,
   including without loaded project access. Retry successfully, then restart and
   confirm metadata/private photos are gone.
7. Enable airplane mode after project context loads; save locally. Log out and
   sign into another account: the first account's drafts must be absent. Return
   to the owner account to check retained drafts. A cold offline launch still
   needs the separately planned persistent project context.

## Remaining limitations

Physical Android/iOS camera behavior, actual Android activity recreation and live
production-account testing remain manual. Unit/router tests and platform exports
do not establish those outcomes. Upload, worker processing and explicit submission
remain in the approved later slices; saving here does not send a report for review.
