# PR: Present the manager overview as the Manager Panel

## Behavior and scope

UI step 8.8 replaces the visual layout of the approved Manager **Overview** tab
with the eighth mobile reference's Manager Panel. The project card, four-part
summary, Timeline Scheduler, recent verified field updates and persistent
Overview / Review / Schedule / History tabs now form the manager persona's home
screen.

The Tasks summary uses accepted-finished activities over planned activities.
Timeline bars show mean backend accepted progress within each discipline,
including partial progress, with accepted-finished counts shown separately. Recent
updates use current effective accepted-history records, show each matched task,
prefer the accepted provenance's recorded reporter label and use a relative
acceptance time. The pending-review count and links to Schedule, History and
Review keep the delivered manager workflows reachable.

## Contract and decisions

- Existing authenticated `schedule_snapshot`, `execution_history`, actionable
  `claims` and membership-recheck reads are unchanged. This slice adds no
  backend call, write, table, RPC, policy, secret or dependency.
- The owner approved using Manager Panel as the existing Manager Overview tab.
  Field Home and its approved navigation remain unchanged.
- Project health, worker count, delays and variance have no approved production
  definition or complete data contract. Each is visibly **Not recorded**; the
  screen does not infer a green health state, count distinct history labels as
  workers, derive schedule delay, or calculate variance.
- A recent update's worker label comes only from
  `provenance.reportedByLabel`. Missing provenance displays **Reporter not
  recorded**. Reviewer names are not presented as field workers.
- Relative timestamps are derived from the server's accepted timestamp and are
  available in English and Hindi. Invalid history timestamps remain rejected by
  the existing runtime schema before rendering.
- Loading, no-project, wrong-role, revoked-access, no-schedule, empty,
  backend-error and cached-offline behavior remains explicit. Offline refresh
  stays disabled.

## Remaining limitations

- Production RLS, cross-client parity and physical-device visual evidence need
  owner-designated accounts and projects.
- Health thresholds, project worker totals, schedule delay and variance remain
  unavailable until their definitions and production contracts are approved.
- Relative time updates when the panel renders or refreshes; it does not run a
  background timer while the screen remains open.
