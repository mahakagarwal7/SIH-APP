# PR: Restyle the Progress Overview screen

## Behavior and scope

UI step 8.6 rebuilds Manager > Overview around the sixth mobile reference. It
adds the **Progress Overview** header, an actual activity-count donut with a
color-coded real-discipline legend, **WORK AREA COMPLETE** bars and a Monday to
Sunday **WEEKLY PROGRESS TREND** chart.

The existing step 6.1 manager behavior remains below those charts: current
claims still link to Review, recent accepted records still link to History, and
loading, empty, wrong-role, revoked-access, error and cached-offline states stay
explicit. Pull-to-refresh replaces the old toolbar without changing refresh or
cache behavior. The approved Manager tabs remain Overview / Review / Schedule /
History.

## Contract and design decisions

- Existing authenticated `schedule_snapshot`, `execution_history`, actionable
  claim and membership-recheck reads are unchanged. This slice adds no backend
  call, write, policy, RPC, secret or dependency.
- The donut is accepted-finished activity count divided by planned activity
  count in the active snapshot. Its exact numerator and denominator are printed
  below it. An empty schedule shows a dash instead of zero-percent completion.
- Discipline legend values and work-area bars use the existing per-discipline
  accepted-finish count ratio. The screen never hardcodes the reference's
  Foundation, Structure or MEP labels.
- The seven daily bars count current effective accepted events by recorded work
  date in the current Monday-to-Sunday site week. Replaced evidence is excluded.
  The chart is labeled as evidence volume, not productivity.
- No weighted schedule completion, quantity conversion, project-health score,
  cost result, variance or forecast is inferred. `docs/MANAGER_OVERVIEW.md`
  records the new count-based display boundary.
- Review attention and recent accepted evidence remain visible so the visual
  change does not remove delivered manager functionality.

## Remaining limitations

- Production-RLS, web/mobile parity and physical-device visual evidence require
  owner-designated accounts and projects.
- The total is an activity-count ratio. Weighted schedule, cost, health,
  variance and productivity measures remain unavailable without an approved
  contract.
- UI steps 8.7 and 8.8 remain separate PRs.
