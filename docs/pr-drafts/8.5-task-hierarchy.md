# PR: Restyle the Task Hierarchy screen

## Behavior and scope

UI step 8.5 rebuilds the read-only task hierarchy around the fifth mobile
reference. It adds the Back, **Task Hierarchy** and settings header, a
**CURRENT TASK** callout, and a vertical connected chain whose colored
percentage circles and labels follow the real source hierarchy at whatever
depth the production snapshot provides.

The chain remains interactive. Selecting an ancestor shows its real path and
direct child branches; selecting a child continues the drill-down. The screen
resets that focus when the project, active revision or schedule version
changes. RLS-limited paths and missing parents remain explicit instead of
inventing hidden nodes.

The bottom action row adds the requested Speak Progress shortcut, native share
sheet and **UPDATE STATUS** action. Both status actions open the existing field
report flow and do not mutate schedule data. Sharing contains only the current
project/task identifiers and accepted percentage already visible to the
signed-in member.

## Contract and design decisions

- Existing authenticated `schedule_snapshot`, membership recheck, React Query
  key and RLS behavior are unchanged. This slice adds no backend write.
- A hierarchy level receives a percentage only when an activity with the same
  exact external ID exists in the authorized snapshot. An accepted actual
  finish renders 100 percent; otherwise the explicit accepted percentage is
  used.
- Summary/parent levels without an accepted activity percentage show a dash.
  The app does not aggregate children, convert quantity into completion or
  copy the selected task's progress into its ancestors.
- The current task callout retains exact accepted quantity, accepted actual
  dates, assignment context, external ID and location.
- UPDATE STATUS and the microphone shortcut open `/field/report`. The existing
  report/outbox/manager-review flow remains responsible for matching and
  accepting evidence; the hierarchy stays read-only.
- The share action opens the platform share sheet only after the worker taps
  it. It does not upload, publish or introduce a new export endpoint.
- Pull-to-refresh retains normal access and revision revalidation. Cached
  offline hierarchy remains visibly labeled and cannot refresh until
  reconnecting.

## Manual device checks

1. Open a task from Field > My work and compare the header, current-task card,
   colored chain, connectors and bottom actions with the fifth phone in
   `Untitled.pdf`, including a small screen and increased font scale.
2. Use projects with shallow and deep source hierarchies. Verify the chain uses
   the real depth and labels rather than forcing the reference's five example
   levels.
3. Compare a hierarchy with accepted parent percentages to one without them.
   Verify exact values appear only for matching activities and missing values
   remain dashes.
4. Select an ancestor, then a direct child. Verify only real source
   relationships appear and returning after a schedule revision resets focus
   to the selected field task.
5. Tap the microphone and UPDATE STATUS controls. Verify both open the field
   report flow and the hierarchy itself performs no schedule write.
6. Open Share, inspect the proposed text, then dismiss it. Verify no share is
   sent until a target is explicitly selected.
7. Repeat offline with cached data and with a deliberately limited membership.
   Verify cached, limited-path and missing-parent warnings stay visible and
   refresh resumes after reconnecting.

## Remaining limitations

- Parent progress is unavailable when production does not expose an accepted
  activity row for that exact hierarchy node; the screen shows a dash rather
  than estimating it.
- UI steps 8.6-8.8 remain separate PRs.
