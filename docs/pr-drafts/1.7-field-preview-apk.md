## Problem and result

Field reporting needs an installable phone build before its real backend and offline paths can be accepted. This slice adds a repeatable Windows build command for an ARM64 release APK with bundled JavaScript, the approved package ID and local debug signing. The command verifies ABI, bundle presence and APK signing before copying the ignored artifact to `dist`.

## Implementation

- Added `npm run android:preview` and a PowerShell build wrapper.
- Loads only the two public Supabase variables from ignored `.env.local`, disables Expo's automatic dotenv fallback and never prints the values.
- Requires complete public configuration by default; the explicit structural-validation switch writes a differently named setup-unavailable APK.
- Uses the installed Android Studio JBR/SDK when environment variables are absent.
- Generates the ignored Expo Android project, initializes Worklets CMake with the required Java native-access option, builds only `arm64-v8a` without parallel Gradle tasks, verifies the APK and reports its checksum. It restores process environment values after direct invocation.
- Added the physical-device acceptance procedure and an evidence record.

The `scripts` directory is outside the incremental target tree because the build must be reproducible without tracking Expo's generated `android` directory.

## Assumptions

- Package ID `com.mahakagarwal.nirmaan` and local development/debug signing were approved by the owner.
- This preview is for an ARM64 Android phone. Store signing and publishing remain separate.
- The production Supabase URL and publishable/anon key remain local public configuration.
