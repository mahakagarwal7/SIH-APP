# PR: Restyle the Speak Progress screen

## Behavior and scope

UI step 8.2 rebuilds the Android voice-report surface around the supplied
mobile reference. It adds a drill-down header with Back and Settings actions,
English and Hindi language pills, a large circular recording control, an
audio-driven waveform, and side-by-side Cancel and Submit actions. The existing
field tab shell keeps Report active.

The recording control is purple while ready and turns red while the microphone
is active. Incoming PCM samples drive the waveform through a bounded RMS voice
level, so it reacts to the actual microphone signal rather than playing a
decorative animation. The duration and 25-second limit remain visible.

Cancel during capture releases the microphone and discards that unsaved
attempt without creating a draft. Submit during capture stops the microphone,
saves the recording on the device, and opens the existing review state. The
same result remains available by tapping the central Stop control.

The review state still appears immediately after local save. Playback,
**Transcribing…**, editable verified wording, and Cancel are unchanged. The
existing Send operation is presented as **Submit** to match the reference; it
still queues the report immediately without waiting for transcription. Typed
details, supporting photos, other input methods and local draft recovery remain
available below the primary voice controls.

## Contract and design decisions

- Production tables, RPCs, storage paths, payloads and RLS behavior are
  unchanged.
- English and Hindi are the only language choices because those are the two
  confirmed v1 languages. Tamil and other reference-only languages were not
  added.
- Language selection uses the existing app-wide locale preference and secure
  local persistence.
- Voice level is calculated locally from the same PCM16 buffers already used
  to create the WAV file. It does not upload or retain additional audio data.
- Cancel before local save creates no durable draft. Cancel from the review
  state continues to use the existing outbox cleanup behavior.
- Submit before review means stop and save locally. Submit in review invokes
  the existing immediate send-request operation from FIXES 7.2.
- Supporting text and photos remain independent optional evidence, preserving
  the seven report combinations verified in FIXES 7.5.

## Manual device checks

1. On the Android development build, compare the header, language pills,
   circular control, waveform and action row with the second phone in
   `Untitled.pdf`, including a small screen and increased font scale.
2. Switch between English and Hindi, restart the app, and verify the selected
   language persists without adding a Tamil option.
3. Start speaking softly and then loudly. Verify the waveform responds to the
   microphone signal, the timer advances and the control turns red.
4. Cancel an active recording. Verify the microphone indicator stops, the
   screen returns to Ready and no local draft appears.
5. Record again and use Submit. Verify navigation to review occurs after local
   save, playback is available, Transcribing appears immediately, and Submit
   can be requested before the transcript finishes.
6. Repeat while offline. Verify the report remains saved on the device and the
   queued send resumes after reconnecting.
7. Add optional text and a photo before recording and verify the combined
   evidence remains one report through review and My Reports.

## Remaining limitations

- Native PCM voice capture remains Android-specific in the current product;
  the existing iOS/web fallback is unchanged by this UI slice.
- UI steps 8.3-8.8 remain separate PRs.
