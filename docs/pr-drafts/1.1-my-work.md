## Behavior and scope

Field > My work now reads the signed-in reporter's assignments instead of showing an unavailable placeholder. It displays the default active project's name, Today / Up next / Earlier assignments, accepted quantities, actual dates and assignment versions. Loading, no project access, no active schedule, empty periods, errors and offline cached work are explicit. Nirmaan design-book page 8 guides the screen.

This is roadmap 1.1 only. The branch depends on `feature/0.3-navigation-shell` ([PR #3](https://github.com/mahakagarwal7/SIH-APP/pull/3)), which depends on auth PR #2 and foundation PR #1. No merge is authorized.

## Contract and decisions

- The owner approved existing authenticated Supabase queries/RPCs under RLS for this slice on 23 September 2026. [The detailed contract](../MY_WORK_CONTRACT.md) identifies the reviewed web source, queries and known consistency limit.
- Uses `project_members`, `projects`, `assignment_versions` and `schedule_snapshot(p_project)`. No raw writes, backend changes, service-role key or native web-cookie workaround.
- Uses the first active membership ordered by project ID, matching the web fallback; project switching remains 2.1. Personal work uses the current assigned reporter, even when the user's role permits broader reads. Assignment dates use IST, matching the web.
- Adds React Query for server state, cancellation and session-scoped caches; Zod validates consumed response fields. No server records enter local UI state or persistent storage.
- Latest assignment versions, stable pages and complete counts are required; detected inconsistent data fails visibly. Independent snapshot/assignment requests cannot establish cross-request transaction atomicity.
- A valid in-memory result is labeled stale offline. Sign-out/account changes clear the cache. Report-status polling, offline outbox storage, capture and translations remain later decisions/slices.

## Manual device checks

1. Fill the ignored mobile `.env.local` public key and restart Expo with `npx expo start --clear`. Sign in with an existing authorized reporter and open Field > My work. Compare project, assignment versions, date groups and accepted quantities with the web's same default project.
2. Verify a reporter only sees their own current assignments. An authorized supervisor/manager must not see another reporter's work as their personal assignments. Verify another project's records are denied using an agreed isolated test environment.
3. In the test environment, exercise no active membership, no active schedule, no assignments and a future/earlier assignment. Expect distinct messages, no invented dates and no quantity-based completion label.
4. Load work, enable airplane mode, revisit the tab and verify the stale-data banner. Reconnect and verify fresh data. Restart while offline: no persistent work cache is promised.
5. Reassign a task or revoke membership through the existing authorized administration flow in the test environment, then Refresh. The old task or project data must disappear. Recover access and retry.
6. Sign out while a work read is pending, then sign in as a different user. No previous user's project/tasks may appear. Background/resume and return from Account or the project placeholder; verify refresh and the selected tab.
7. Check 320-pixel/large-text layouts, native scrolling, screen-reader headings and button states, and local midnight in a phone timezone different from IST. Past assignments must never imply completed work.
