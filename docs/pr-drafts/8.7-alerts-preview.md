# PR: Add the Alerts & Approvals design preview

## Behavior and scope

UI step 8.7 adds a protected `/alerts-preview` route that matches the seventh
mobile reference: **Alerts & Approvals** header and settings control, All /
Critical / Pending filters, red critical, green approved and amber pending
cards, preview detail actions, and the reference Alerts-selected bottom bar.

This is deliberately a design preview. A prominent banner says no live alerts
or approvals are connected, every card says Demo or Example, and selecting View
Details explains that no live record exists. Filters and count badges operate
only on three in-memory fixtures.

## Contract and design decisions

- This slice imports no Supabase client, calls no API/RPC/Storage operation,
  creates no notification subscription and performs no approval action.
- The route remains behind the existing signed-in `(app)` boundary. A route
  test covers signed-out rejection and signed-in access.
- The preview has no link from production workflows. It is available only at
  `/alerts-preview` for design review, so it cannot be mistaken for delivered
  alert functionality.
- The approved Field tabs Home / Report / My work / My reports and Manager tabs
  Overview / Review / Schedule / History are unchanged. The five-item bar on
  this preview is static reference artwork, labeled as a navigation preview for
  assistive technology.
- Critical and Pending badges count the actual local fixtures. The app does not
  copy the illustrative 2/5 counts from the PDF or imply production counts.
- Filter changes clear prior preview feedback. Critical and Pending each show
  only their corresponding local fixture; approved content remains in All.
- English and Hindi copy cover every new visible and accessibility phrase.
- Alerts/push scope, backend contracts, delivery rules and real navigation
  remain unresolved in `CODEX.md` and `docs/PROJECT_REVIEW.md`.

## Manual device checks

1. Open `/alerts-preview` while signed in and compare the header, filter pills,
   colored cards, icons, borders, View Details controls and bottom bar with the
   seventh phone in `Untitled.pdf`.
2. Verify the preview banner and Demo/Example language remain visible without
   scrolling and cannot be confused with production alerts.
3. Select All, Critical and Pending. Verify counts stay at one, each scoped
   filter shows only its matching fixture, and approved content appears under
   All.
4. Tap every View Details control. Verify only a preview-only local message
   appears and no navigation, network request or approval occurs.
5. Test English and Hindi at default and increased font scale on a narrow
   device. Verify pills remain usable, descriptions wrap, and the tab artwork
   stays readable.
6. Sign out and deep-link to `/alerts-preview`. Verify the authentication
   boundary shows sign-in rather than any fixture card.
7. Verify the normal Field and Manager tab bars and all live Review decisions
   remain unchanged.

## Remaining limitations

- This route is not a production Alerts feature. Real events, counts, relative
  times, details, approval actions, push delivery and navigation require an
  owner-approved product/backend contract.
- The static reference tab bar is intentionally noninteractive and does not
  replace the approved workspace navigation.
- UI step 8.8 remains a separate PR.
