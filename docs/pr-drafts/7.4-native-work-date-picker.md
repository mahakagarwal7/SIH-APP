# PR: Replace report date text fields with native calendar controls

## Behavior and scope

FIXES step 7.4 replaces every editable `YYYY-MM-DD` field in the report flow
with one shared work-date control. Field confirmation, manager correction and
report clarification now open the platform calendar on Android and iOS. The web
fallback uses the browser's date control so the existing static web build keeps
working without restoring free-text entry.

An empty control remains **Not recorded**. Opening it stages today's date in the
device's local timezone, but it does not write or submit that date until the
user confirms the calendar selection. Selected values display as readable local
calendar dates. Users can explicitly clear a selected date where the backend
contract permits `null`.

The same local validation now guards field confirmations, manager corrections
and clarification replies. Invalid or future dates cannot reach the existing
production submission contracts.

## Contract and decisions

- Existing production Supabase tables, RPCs, RLS policies and payload shapes
  are unchanged. Dates still cross the boundary as `YYYY-MM-DD` or `null`.
- `@react-native-community/datetimepicker` 9.1.0 is the Expo SDK 57-compatible
  native dependency and supplies the Android/iOS calendar.
- Calendar comparisons use device-local year, month and day fields. They do not
  convert through UTC or the app's display timezone.
- Today and past dates are accepted. `maximumDate` blocks future selection, and
  contract validation rejects a future value defensively.
- An empty field opens at today for convenience but remains `null` unless the
  user presses the Android dialog confirmation or **Use date** on iOS.
- The clarification history also formats stored work/event dates with the same
  readable local formatter.

## Manual device checks

1. Open a new field confirmation with no date. Verify **Not recorded** appears,
   then open and cancel the picker. Confirm the submitted payload still has no
   work date.
2. Reopen the picker and verify it starts on the device's current local date.
   Confirm a past date and verify the readable date appears in the field.
3. Verify the platform picker prevents choosing tomorrow or any later day.
4. Clear an optional date, submit the report and verify My Reports and manager
   review still show **Not recorded** rather than today's date.
5. As a planner, open a claim that requires a missing date. Confirm preview is
   disabled until a calendar date is selected, then verify the preview carries
   the selected `YYYY-MM-DD` value.
6. As a reporter, answer a work-date clarification and verify only a confirmed
   calendar selection enables **Send answer**.
7. Change the device timezone across midnight and repeat steps 1–3. Verify the
   picker uses that device's local day and never advances the stored date via a
   UTC conversion.
