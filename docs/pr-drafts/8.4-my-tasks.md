# PR: Restyle the My Tasks screen

## Behavior and scope

UI step 8.4 rebuilds the field worker's assigned-work screen around the fourth
mobile reference. It adds the avatar, **My Tasks** and settings header, a
purple date navigator with previous/next day controls, and compact white task
cards with colored status rails, status icons, accepted-progress bars and the
specified **DONE**, **WORKING**, **START** and **DELAYED** treatments.

The date controls filter the already-loaded assignment snapshot by each
assignment's inclusive effective dates. Stepping between days is immediate and
does not issue another production read. The selected day follows the India
site date across midnight only while the worker has not navigated away from
today. Pull-to-refresh remains available for an explicit server refresh.

Each task card keeps the production name, external ID, location and exact
accepted quantity. Tapping a card opens its existing read-only task hierarchy.
The header settings action opens the existing account/project controls.
Loading, no-access, no-schedule, empty-date, error, offline-cache and retry
states remain explicit.

## Contract and design decisions

- Existing authenticated `schedule_snapshot`, `assignment_versions`, project
  membership and RLS paths are unchanged. This slice adds no writes or backend
  contract.
- A task is **DONE** only when it has an accepted actual finish. Its bar is
  then 100 percent.
- An unfinished task is **DELAYED** only when its recorded planned finish is
  before the current India site date. **WORKING** requires an accepted actual
  start or a positive accepted percentage. Other assigned tasks show
  **START**.
- Partial bars use only the explicit accepted percentage, bounded to 0–100.
  Accepted quantity is displayed separately and never converted into a
  completion percentage.
- Date navigation selects assignments effective on that date. The production
  snapshot contains current accepted status rather than a daily status
  history, so navigating to an earlier day does not claim to reconstruct the
  task's status as it existed then.
- The approved field tab label remains **My work** while the screen heading
  follows the reference's **My Tasks** copy.
- The START presentation opens the task hierarchy/report path and does not
  edit schedule actuals from this read-only list.
