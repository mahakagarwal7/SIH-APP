## Behavior and scope

**TL;DR:** Adds Check → Send for verified voice/photo reports and offline text-only reports. Fixes the 11 review findings, integrates the owner-merged PRs 1–7 from main `5d23479`, and retains account isolation, guarded drafts, retryability and the repaired navigation. The PR targets main and is not merged by the agent.

Voice keeps the verified original transcript visible beside editable submitted wording. Workers can record an optional work date, choose from current RLS-scoped activities and must explicitly check quantities and unfinished-work wording before confirmation.

The exact normalized submission payload is written to the account-scoped SQLite outbox before any network attempt. Offline confirmation, restart and lost responses reuse the same report ID, wording, work date and activity. A verified RPC receipt moves the item to Awaiting review and releases private local evidence; it never claims planner acceptance.

This PR changes no production schema, RLS policy, web route or worker.

## Contract and decisions

- Uses existing `schedule_snapshot(p_project)` and current active membership to show only RLS-visible activity options.
- Uses existing `submit_field_capture(p_report, p_text, p_work_date, p_activity)` exactly; the RPC rechecks authorship, membership, activity access and media readiness.
- Keeps work date and activity optional because that is the production contract. Missing work date is displayed as Not recorded.
- Keeps unfinished work in the confirmed wording because production exposes no partial-work boolean or pre-submit AI match.
- Stores verified voice transcript, confirmed payload, receipt state and evidence cleanup state through an additive SQLite migration.
- English UI ships in this slice under approved language order; the later localization slice owns Hindi completion.

## Manual device and production checks

1. Supply the publishable key locally and sign in as a scoped reporter. Upload a real voice capture and wait until My reports shows Needs confirmation.
2. Tap Check and send. Verify the server transcript is read-only, editable wording starts from it, missing work date says Not recorded, and activity choices match current authorized work.
3. Correct the wording, explicitly retain unfinished quantities, select a work date/activity and confirm. Verify the production planner web app receives one report in review and mobile says Awaiting review rather than Accepted.
4. Repeat with a text-only and photo report. Confirm photo captions/evidence remain linked and the exact edited text reaches review.
5. Go offline before confirming. Save, force-stop and reopen. Confirm the wording/date/activity stay locked, then reconnect and verify one report is submitted.
6. Interrupt the network after the submit request. Use Check receipt / retry and confirm no duplicate report/version/job is created and the payload cannot be edited.
7. Revoke project membership before send. Confirm submission pauses without deleting evidence. Restore valid access and retry.
8. Sign into another account and verify the first account's confirmation remains hidden.
9. After a valid receipt, verify the private local voice/photo draft is removed while the outbox/server status remains visible.
10. Make a selected activity unreadable before the first send. Verify the specific rejection permits a corrected selection and requires a fresh confirmation; generic auth/network errors must keep the payload locked.
11. Confirm a new text-only draft while offline before any reservation, reopen its confirmation from My reports, and verify wording/date/activity survive restart and deliver once after reconnect.
