# PR: Add the in-app photo viewfinder

## Behavior and scope

UI step 8.3 replaces the native photo-report form with the full-screen camera
surface from the supplied mobile reference. The viewfinder includes a subtle
three-by-three grid, transparent Back, flash and camera-flip controls, a photo
strip with a library add tile, a large white shutter and a retake action. The
current project remains visible in the top overlay.

A shutter photo appears in the strip as soon as the native camera returns it.
The existing bounded JPEG preparation then runs in the background, and the
worker can keep using the viewfinder until the three-photo limit is reached.
Each photo retains its own optional caption. Save on device becomes available
only after every attached photo is prepared, so the app never claims that
incomplete bytes are durable.

The viewfinder also presents camera-permission, camera-mount, offline, draft
recovery, compression and persistence states. Library selection uses the same
background preparation path as camera capture, and Retake removes the latest
attachment without locking the remaining controls.

## Contract and design decisions

- `expo-camera` `~57.0.5` supplies the native Android/iOS viewfinder, camera
  permission, flash, lens switching and still capture. The config plugin does
  not request Android audio recording or enable barcode scanning.
- Camera output is accepted through the same structural local-photo contract
  as image-picker output. Existing `expo-image-manipulator` size, quality and
  five-MiB limits remain unchanged.
- Immediate attachment means the native cache image is visible once
  `takePictureAsync` resolves. Compression starts without blocking another
  shutter action. Durable app-private storage still requires the explicit
  Save on device action after all attached photos are ready.
- Production tables, RPCs, storage paths, payloads, authentication and RLS
  behavior are unchanged.
- Text reports retain the existing form. The generic web fallback is unchanged
  because a native camera surface is an Android/iOS capability.
- The three-photo limit and per-photo caption contract remain unchanged.

## Manual device checks

1. Install the generated preview on an arm64 Android device and compare the
   grid, overlay controls, thumbnail strip, shutter and retake placement with
   the third phone in `Untitled.pdf`, including a small screen and increased
   font scale.
2. Deny camera permission, then grant it from the prompt. Verify the permission
   state recovers and the live viewfinder mounts.
3. Toggle flash on the rear camera, take a photo, switch to the front camera and
   take another. Verify both thumbnails appear immediately and remain tied to
   the report.
4. Capture three photos rapidly while preparation is slow. Verify the shutter
   remains usable through the third photo, then disables at the documented
   limit while Save stays disabled until all preparation finishes.
5. Select each thumbnail, enter distinct captions, retake the latest image and
   verify the remaining captions stay with their original photos.
6. Add a library image with the plus tile, save the report and verify the actual
   photo bytes and captions survive app restart and appear in My Reports.
7. Repeat capture and save offline. Verify the local report remains available
   and its existing outbox delivery resumes after reconnecting.
8. Background the app and navigate away from the route. Verify the camera stops
   when unfocused and resumes safely after returning.

## Remaining limitations

- Native camera quality, flash behavior and lens availability still require a
  physical-device pass because Jest and the release build cannot exercise
  camera hardware.
- UI steps 8.4-8.8 remain separate PRs.
